# 校园跑腿平台前端

Vue 3 + Vite + Vue Router。当前实现前端 B 的任务执行、钱包、通知、取消与申诉、管理端页面。注册登录、任务大厅、发布/修改/撤回页面由前端 A 接入；个人中心、评价、信用分展示和收益统计未纳入本次开发。

## 运行

需要 Node.js `^20.19.0 || >=22.12.0`。

```bash
npm ci
npm run dev:apifox
```

打开终端显示的地址，默认是 `http://localhost:5173`。`dev:apifox` 使用 `.env.apifox` 中从项目云端 Mock 页取得的服务地址，通过 Vite 代理调用 `/api/v1`；无需在前端保存 Apifox 登录凭证。Mock 模式不向云端转发本机 Session Cookie / Authorization，也不接受云端 Cookie 覆盖本机会话。

[Apifox 项目](https://app.apifox.com/project/8940624)当前使用自动随机响应；它能验证请求路径、字段和代理联通，但不能保证筛选条件、当前用户与参与者关系、跨请求状态和统计总数一致。不要把随机 Mock 中的状态变化或金额当作业务验证结果。浏览器场景测试使用单独的固定接口拦截，不会混入产品代码或作为真实接口失败后的替代数据。

连接本机 Spring Boot：

```bash
npm run dev
```

默认 `/api`、`/actuator` 代理到 `http://localhost:8080`。可参考 `.env.example` 创建被 Git 忽略的 `.env.local`，配置 `API_PROXY_TARGET`；若希望保留 `dev:apifox` 的专用目标，请把本机配置放在 `.env.development.local`。更改环境变量后重启 Vite。

生产构建默认使用同源 `/api/v1`，部署时由服务器反向代理 API，并为前端路由配置 SPA fallback。仅在确实需要跨域部署、且服务端已配置带凭据 CORS 时设置 `VITE_API_BASE_URL`。

## 页面与现有契约

| 路由                | 已实现内容                                                                         |
| ------------------- | ---------------------------------------------------------------------------------- |
| `/my-tasks`         | 我接取的 / 我发布的，状态筛选、0 起始分页、10/20/50 条切换、任务统计、任务操作入口 |
| `/my-tasks/:taskId` | 任务执行详情，按身份和状态接单/送达/验收，申请取消、提交申诉、投诉                 |
| `/wallet`           | 可用/冻结余额，本人流水，类型筛选，关联任务及申诉编号                              |
| `/notifications`    | 全部/未读通知、未读总数、单条已读、关联任务跳转                                    |
| `/disputes`         | 按申请编号应答取消；可用 `?requestId=...` 预填                                     |
| `/admin`            | 取消争议裁决、已完成任务申诉裁决、投诉处理，以及用户/任务/流水/日志查询            |

所有页面依赖 `/api/v1/auth/me` 的服务端登录态；没有模拟登录或客户端选择角色的功能。普通账号不能进入管理路由；服务端仍须校验所有查询和操作权限。真实后端登录模块尚未接入时，可先使用 `dev:apifox`。

写操作先请求 `/api/v1/auth/csrf`，再携带 `X-XSRF-TOKEN` 和 Session Cookie。客户端解析统一响应，保留 HTTP 状态及业务错误码；失败明确提示，不自动重试写操作。快速切换列表条件时取消旧查询，避免旧数据覆盖新筛选结果。

## 前端 A 的接入点

- `src/router.js` 导出 `frontendBRoutes`，可合并到公共路由。
- `src/components/TaskActions.vue` 可在任务大厅/详情中复用。传入契约 `Task`，`compact` 模式只显示接单/送达/验收操作；`refresh` 事件用于重新读取任务。
- 共享登录身份保存在 `src/composables/state.js` 的 `session`；登录模块成功后可更新该值。退出或切换账号时须清空旧会话状态，再读取当前用户。
- 当前单独提供 `/my-tasks/:taskId` 执行详情和“按编号查看任务”入口，避免占用前端 A 的任务大厅路由。
- 统一接口客户端在 `src/api/client.js`，业务方法在 `src/api/index.js`。ID 以字符串传递；不提交操作者 `userId` / `role` 或任意目标状态。

## 尚需补齐的公共契约

本次没有自行添加公共 OpenAPI 路径或字段。以下为已分配功能中的接口缺口，需对接后端后才能完成对应联调：

1. **本人取消申请/申诉的列表与详情**：当前仅有创建、应答及管理员查询。已提供按申请编号应答与提交结果编号；未伪造个人历史查询。通知模型仅包含 `relatedTaskId`，不能自动定位取消申请编号。完整处理结果回看也依赖该查询契约。
2. **任务上的活动取消争议**：`Task` 未返回活动取消申请或争议冻结标记，前端无法在重新打开页面时准确禁用送达/验收。服务端必须拒绝争议期间的非法操作；后续需补可展示的状态字段。
3. **异常任务处理**：尚无异常队列、强制关闭/转派等业务接口。未添加通用改状态入口，也未模拟异常处理成功。
4. **管理端任务范围**：当前复用已定义的 `GET /tasks` 及状态/关键字参数；管理员全量可见范围、按发布者与时间查询，仍须后端明确或补契约。
5. **投诉扩展能力**：当前支持契约内的投诉文字提交和处理手段。证据图片上传、功能限制期限、第二管理员复核尚无完整契约，未提供相应操作。扣分依据记录在既有 `decisionNote` 中，未新增请求字段。
6. **时间筛选与全部已读**：本人任务历史日期、钱包/管理查询时间筛选、通知全部已读等尚无完整参数/接口，未用单页数据计算全局结果或伪造批量操作。
7. **详情补充信息**：当前 `Task` 仅定义参与者编号和发布时间等最小字段；接单/送达/完成时间、联系方式与完整状态日志需要后端补齐。

## 验证

```bash
npm test
npm run build
```

Node 测试覆盖接单资格、截止时间边界、送达/验收权限、取消与申诉边界、裁决金额约束、CSRF、网络/HTTP 错误和响应格式。

浏览器验证脚本为 `tests/browser-smoke.js`，通过 Playwright CLI 执行，依赖已启动的 `http://127.0.0.1:5173`。它拦截该浏览器会话中的 `/api/v1`，验证成功和失败场景，不访问真实账务数据。可使用 CLI 的 `--config` 参数选择机器上已安装的浏览器。

```bash
npx --yes --package @playwright/cli playwright-cli -s=frontend-b open http://127.0.0.1:5173/my-tasks
npx --yes --package @playwright/cli playwright-cli -s=frontend-b run-code --filename tests/browser-smoke.js
```

截图和浏览器临时输出位于被 Git 忽略的 `output/playwright/`。最终联调仍须由两个普通账号与一个管理员账号，接真实后端验证事务、并发、幂等和权限；浏览器固定场景不能代替后端验证。
