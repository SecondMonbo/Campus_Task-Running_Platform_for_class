# 任务发布接口核查说明（Part A）

> 本文件记录后端对「Part A：任务发布与任务主流程」的核查结论。
> 契约以 `code/development_doc/openapi.yaml` 为准。按项目要求，本次未修改
> `code/development_doc/` 下的任何文件。

## 结论

`POST /api/v1/tasks` 已实现且满足 Part A 约定，本次**没有重复实现**，只删除了响应视图中
前端从未使用的预留字段。

## 现有实现核查

| 检查项 | 结论 |
| --- | --- |
| 路由 | `TaskController.createTask`：`POST /api/v1/tasks`，成功 201 |
| 身份 | 操作者来自 `CurrentUserService.requireCurrentUser()`，请求体不接受 `userId`/`role` |
| 字段校验 | `TaskCreateRequest`：标题非空 ≤100、描述非空 ≤2000、报酬 1–1000、截止时间 `@Future`、地点非空 ≤200 |
| 报酬冻结 | `TaskService.createTask` 先 `AccountingService.freeze`，再保存任务；同一事务，余额不足整体回滚并返回 409 `INSUFFICIENT_BALANCE` |
| 留痕 | 发布成功写入 `task_operation_log`（action=`PUBLISH`） |
| 响应 | 统一 `{code:"OK",message:"success",data:Task}`；`publisherId`/`runnerId` 为字符串 |
| 大厅可见性 | 新任务状态为 `WAITING_FOR_TAKER`，`GET /api/v1/tasks` 按 `publishedAt` 倒序返回 |
| 状态操作 | 接单使用 `findByIdForUpdate` 悲观锁；送达/确认完成校验参与者与状态；重复操作返回 409，幂等 |
| 测试 | `TaskServiceIntegrationTest`、`TaskControllerTest` 已覆盖发布成功、余额不足、状态流转、权限与并发 |

## 本次代码改动

- `task/dto/TaskView.java`：删除 `acceptedAt`、`deliveredAt`、`completedAt`、`cancelReason` 四个
  响应字段及其 getter。它们不在 `openapi.yaml` 的 `Task` schema 中，前端也从未使用。
- `Task` 实体与 `task` 表列保持不变，时间戳仍按业务动作写入数据库，仅不再出现在 API 响应里。
- 未修改接口路径、请求字段、状态码、事务边界、账务服务或数据库迁移。

## 需要关注但本次未改的点

- `CreateTaskRequest` 未拒绝未知字段，而契约写了 `additionalProperties: false`。这属于全局 JSON
  反序列化策略，改动会影响所有接口，本次不动，等确认后再统一处理。
- 截止时间在应用层校验（`@Future` 与接单时的当前时间比较），数据库层没有对应约束。
